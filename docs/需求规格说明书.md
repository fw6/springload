# 0. 产品命名与品牌规范

## 0.1 正式命名

英文正式名：Springload（首字母大写，全篇统一，不得写作 SpringLoad / springload / Spring-Load）

中文正式名：蓄势

产品副标题（界面与官网使用）：回调买入法工作台

Slogan：压住弹簧，等它弹起。用于启动页与官网首屏；App 内不重复出现。

## 0.2 命名由来（品牌一致性说明，不进界面）

回调买入法的动作本质是：股价向上冲完一波，向下压缩蓄力，再向上弹起。这与弹簧被压缩后释放的物理过程同构——压缩得越紧、松手越稳，弹起越快。Springload 一词同时命中三个产品要点：回调（压缩）、支撑位（弹簧压到底的那道地板）、止损（弹簧压过头就作废）。

## 0.4 图标与视觉规范

主图标意象：一根被垂直压缩的弹簧，弹簧底端压在一道水平线上。三个视觉要素与产品逻辑一一对应，设计时必须保留：

- 压缩的弹簧：代表回调蓄力过程，圈数建议 3~4 圈，压缩到接近极限。

- 弹簧底部的水平线：代表支撑位与止损位，是整套策略里最关键的那条线，需与弹簧明显区分（建议加粗或用实线）。

- 弹簧上方的向上箭头：代表 3R / 5R 目标位，短促上扬，不画成无限上升的曲线（避免暗示收益无限）。

配色：主色建议深蓝或墨绿（专业、克制），禁止使用高饱和红绿涨跌色作为主色——避免诱导性联想。动效仅限启动页的弹簧压缩回弹一次，App 内不做动画。

## 0.5 文案与语气

语气：克制、教学式、不煽动。禁止出现“稳赚”“必胜”“跟上操作”“躺赚”等诱导性表述。

术语一致性：全篇统一使用本文档第 2 章术语表的译法与写法，不得混用全称与缩写（如不得一会儿写 AVWAP、一会儿写“成交量加权均价”而不加注）。

风险表述：凡是涉及收益、胜率、目标位的地方，必须同时出现对应的风险提示，不得只呈现乐观面。

## 0.6 命名禁区

- 不得在名称、slogan、图标中暗示任何收益数字或冠军背书（如“969.8%”“冠军同款”），理由见第 8 章合规要求。

- 不得使用“抄底”“接飞刀”等易被误解为逆势买入的表述——本策略只在强势股回调时买入，与抄底完全相反。

- 不得在名称中出现 AI、智能、量化、跟单等词，避免用户对能力边界产生误判。

# 1. 项目目标与用户场景

## 1.1 一句话目标

为“回调买入法”（Pullback Entry）交易者提供一个桌面端工作台：从强势股池筛起，标注支撑区，生成带止损位的买入计划，并给出仓位股数，全程不依赖用户手动计算。

## 1.2 目标用户画像

股票新手，能看懂股票代码与 K 线图，但不知道 EMA、AVWAP、R 倍数、滑点等术语。因此：

- App 内出现任何术语时，必须附带悬浮提示（tooltip）或内联白话解释，解释文案见第 8 章“术语表”。

- 所有输入框默认带示例值与单位（如“每股风险（美元）：0.50”）。

- 所有数字必须可复算：用户输入任何一组参数，App 必须能反推出仓位股数与风险金额，且与第 5 章公式一致。

## 1.3 非目标（明确不做）

不做自动交易、不对接券商下单。App 只做“计划生成 + 记录”，执行由用户在自己的券商完成。

不做回测引擎、不做收益曲线模拟、不做荐股。App 不判断“这只股票值不值得买”，只判断“如果买，止损与仓位该怎么设”。

不做实时行情。数据来源由用户导入（CSV）或可选的行情 API 接入（见第 4 章），App 不对数据真实性负责。

下表同时承担两项职责：一是给 Coding Agent 建立领域模型，二是直接作为 App 内“术语悬浮提示”的文案来源。

| **术语** | **App 内的白话解释** | **在 App 里的落点** |
|----|----|----|
| 回调买入法 | 股票涨过一波后休息（横盘），等它再次走强时上车，而不是追着已经涨高的价格买。 | 筛选器筛选条件、第 3 页策略卡片 |
| EMA 9/21/50 | 最近 9/21/50 天股价的平均成本线。9 日看短线、21 日看中短线、50 日看中期。 | 图表叠加指标、第 1 步筛选条件 |
| 支撑区 | 股价跌到这个价格附近就容易跌不动的区域，通常叠在均线、前期高点、AVWAP 附近。 | 第 2 页标注组件、支撑区输入 |
| 跳空缺口 | 昨天收盘价与今天开盘价之间那段没有成交的价格区间，常成为支撑/压力。 | 第 2 页标注组件 |
| AVWAP | 从某个指定起点开始，按成交量加权算出的平均成本价，约等于那段时间参与者的平均成本。价格回到这里附近常获得支撑。 | 第 2 页标注组件、需支持自定义起点 |
| 第一次回测 | 股价刚站上某个关键位，回头又踩它一脚。踩住 = 支撑有效，是这套策略最看重的触发场景。 | 买入信号提示文案 |
| R（风险单位） | 这一单预设的最大每股亏损额（买入价 − 止损价）。全程用它衡量盈亏，不用百分比。 | 第 3 页仓位计算核心变量 |
| 3R / 5R 目标位 | 盈利达到 3 倍或 5 倍初始风险的价位。3R 卖出一部分，5R 再卖一部分。 | 第 4 页目标位自动计算 |
| 滑点 | 按下买入那一刻，实际成交价比看到的价格差了一点。会导致实际亏损大于预设值。 | 风险提示文案、第 4 页可选设置 |
| 试错成本 | 这单如果错了，会亏掉的钱。策略的核心是用极小的试错成本换大段上涨。 | 第 3 页风险摘要卡 |

# 4. 四步工作流与算法规格

四步与交易顺序严格对应：F1 产出候选池 → F2/F3 确定支撑区 → F4 等待触发 → F5/F6 生成计划与减仓方案 → F8 跟踪 → F9 复盘。用户不可跳过前序步骤直接算仓位，App 应明确提示“先完成支撑区标注”。

## 4.1 第 1 步：强势股筛选（F1）

### 输入参数

- 近 1 / 3 / 6 个月涨幅阈值（默认 30%）。

- 涨幅排名区间（默认前 20%~30%）。

- 剔除条件：日均成交量低于阈值的品种（默认阈值需可由用户设定，单位“万股/日”）。

- 市场范围：默认美股（与原文策略市场一致），架构上预留 A 股、港股数据源切换接口。

### 判定条件（必须同时满足才进入观察名单）

- C1 涨幅条件：近 6 个月涨幅 \> 阈值，且近 1 个月涨幅排名为前 20%~30%。

- C2 结构条件（回调低点逐渐抬高 + 波动收敛）：当前回调低点 \> 上一次回调低点（如本次 19 美元 \> 上次 18 美元）；近 20 日最高价与最低价之差 / 均价 \< 阈值（默认 0.08，即 8%）。

- C3 均线条件：收盘价 \> EMA9，且 EMA9 与 EMA21 走平或向上。

- C4 排除条件（命中则不入选）：高点与低点均下降，且收盘价 \< 向下的 EMA21。

### 输出

观察名单表：股票代码、近 6 月涨幅、是否满足 C1~C4、所属板块（用于“同板块多只走强”提示）。

## 4.2 第 2 步：支撑区标注（F2 / F3）

图表组件要求：

- K 线图支持日线 / 周线（筛选阶段）与 1 分钟 / 5 分钟 / 15 分钟（触发阶段）切换。

- 可叠加指标：EMA9、EMA21、EMA50、AVWAP（起点可设为“整理区阶段高点”或任意指定日期）。

- 标注类型：水平线（前期高点/低点）、区间框（支撑区）、缺口标记（跳空缺口）。

- 支撑区得分：当 AVWAP、EMA21、前期高点三者价格落点在 ±2% 范围内时，标记“高置信支撑区”，并在卡片上高亮。

## 4.3 第 3 步：买入信号（F4）

两级触发，缺一不可：

- 前置条件（日线）：价格已站上支撑区，且该支撑区为高置信支撑区（见 4.2）。

- 触发条件（分钟图）：先出现一次下探后回升，随后某一根 K 线的最高价 \> 前一根 K 线的最高价，此时在图上标出“触发信号”。

- 若价格直接跌穿支撑区且未回升：不触发，保持“等待”状态，不做任何提示。

信号给出后，App 进入“可下单”状态，自动跳转或引导用户进入第 4 步的仓位计算。

## 4.4 第 4 步：仓位计算与目标位（F5 / F6）

### 输入

- 买入价 entry（美元/股）

- 止损价 stop（美元/股，可取自“当天低点”或“突破 K 线 / 前一根 K 线低点”）

- 账户净值 account（美元）

- 单笔风险比例 risk_pct（默认 0.5%，上限建议 1%）

### 计算公式（必须逐项展示给用户，便于小白理解）

- 每股风险 per_r = entry − stop（单位：美元/股）

- 本单最大可亏金额 max_loss = account × risk_pct

- 可买股数 shares = floor(max_loss ÷ per_r)

- 投入金额 capital = shares × entry

- 仓位占比 pos_pct = capital ÷ account

- 止损距离（占买入价）= per_r ÷ entry

### 校验与提示

- 若止损距离 \> 3%，弹提示“止损过远，超出该策略建议的 2.5%~3%，请重新选择止损位或放弃该标的”，不阻止提交但显著警告。

- 若 entry ≤ stop，报错“买入价必须高于止损价，请检查输入”。

- 若 shares = 0（每股风险过小导致可买 0 股），提示“每股风险过小，请检查止损位或降低风险比例”。

- 3R / 5R 目标位：t3 = entry + 3 × per_r，t5 = entry + 5 × per_r，均不计交易成本。默认在 3R 卖出 1/3 仓位、5R 再卖出 1/3，剩余 1/3 跟踪。

### 示例（写死在示例面板，供小白对照）

账户 10,000 美元，entry = 20.00，stop = 19.50 → per_r = 0.50；max_loss = 50；shares = 100；capital = 2,000（占 20%）；止损距离 2.5%。3R = 21.50，5R = 22.50。

## 4.5 交易计划卡（F7）

将下列字段组合为一页可读卡片，支持一键复制为文本或导出为 PNG/PDF：标的代码、所属板块、日线筛选结论（C1~C4 是否全中）、支撑区价格、AVWAP/EMA21/前期高点三者的价格、买入价、止损价、3R/5R 目标位、仓位股数、投入金额、止损距离、计划风险（占账户 %）。

## 4.6 持仓跟踪（F8）

用户输入已买入价格与止损价后，App 持续（或手动刷新）检查最新价。触发下列任一条件时提示：跌破止损价 → “触发止损，按计划离场”；跌破 9 日 EMA → “趋势可能走坏，建议评估离场”；价格达到 3R / 5R → “到达减仓目标位”。剩余仓位默认跟随 9 日 EMA，EMA 被跌破即离场。

## 4.7 交易日志与统计（F9）

记录字段：标的、入场日、买入价、止损价、出场价、出场日、R 倍数盈亏、备注。统计：交易笔数、胜率（盈利笔数 ÷ 总笔数）、平均 R 倍数（每笔盈亏 R 的均值）、总盈亏（美元）。统计口径必须在界面上标注“未计入交易成本与滑点”。

# 7. 技术指标算法要求

以下算法由前端或本地计算引擎实现，必须支持单元测试，测试用例如下：

| **指标** | **算法** | **必填测试** |
|----|----|----|
| EMA(n) | 指数移动平均：EMA_t = price_t × α + EMA\_(t-1) × (1−α)，α = 2/(n+1)。首值取前 n 个收盘价的简单平均。 | n=9 时与已知序列前 3 位小数一致 |
| AVWAP | 从起点 bar 起，累计 (价格_t × 成交量_t) ÷ 累计成交量_t。起点可选：整理区阶段高点、指定日期、首次信号日。 | 起点变更后曲线整体重算，不得沿用旧值 |
| 涨幅 | (当前收盘价 − N 日前收盘价) ÷ N 日前收盘价。N ∈ {21, 63, 126} 对应 1/3/6 个月（交易日近似）。 | N=0 或数据不足时返回 null 并提示 |
| 波动收敛 | 近 20 日 (最高价 − 最低价) 的均值 ÷ 20 日均价 \< 0.08。 | 等于阈值时算不通过 |
| R 倍数盈亏 | (出场价 − 买入价) ÷ per_r；做空或反向仓位本期不做。 | 出场价 = 止损价时结果为 −1 |

# 8. 边界条件、风险提示与不实现清单

以下条款必须在首屏或设置页以明显方式呈现，属于产品合规要求，不是可选项。

- 高收益不可复制提示：原文所述 969.8% 为 2025 年单场赛事的 12 个月战绩，不是年化收益率，不代表可持续收益。App 不得以任何形式展示或暗示“使用本工具可复现该收益”。

- 市场风险提示：策略收益依赖市场环境，在趋势走坏年份会连续触发止损。App 日志统计应始终标注“未计入交易成本与滑点”。

- 市场风险补充：A 股存在涨跌停与 T+1 制度，当日买入无法当日卖出，止损单可能无法成交导致实际亏损远超预设。App 在市场选择为 A 股时，必须显示该提示。

- 滑点提示：跳空或滑点会使实际成交价劣于预期，亏损可能超过预设的账户风险。仓位计算结果标注“理论值”。

- 不做自动交易、不做投顾建议、不提供实时行情、不判断标的投资价值。

- 数据缺失：价格数据不足时，相关指标显示“数据不足”，不得用 0 或旧值替代计算。
