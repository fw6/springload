# 东方财富与腾讯行情接口的参数与字段规格

对应 issue：`fw6/springload#2`。

三家接口都没有官方文档。本文的全部结论来自 2026-10-13 当天实际发起的 HTTP 请求，每条结论都附上请求用的完整 URL 与返回片段。凡本轮请求无法确定的，列在最后一节「未能核实」。

调查环境：curl 8.7.1，macOS，直连公网。文中所有价格数值取自 2026-10-13 12:00 前后的盘中快照。

## 一、东方财富 K 线接口

### 1.1 请求

```
https://push2his.eastmoney.com/api/qt/stock/kline/get
```

同一路径在 `push2.eastmoney.com` 上也返回 200：

```
https://push2.eastmoney.com/api/qt/stock/kline/get?secid=1.600000&ut=fa5fd1943c7b386f172d6893dbfba10b&fields1=f1,f2,f3&fields2=f51,f53&klt=101&fqt=1&end=20500101&lmt=2
```

返回头 `Content-Type: text/plain`，`Access-Control-Allow-Origin: *`。

请求参数：

| 参数 | 是否必需 | 说明 |
| --- | --- | --- |
| `secid` | 必需 | 证券标识，格式 `<market>.<code>`。`market` 为 `1` 表示上海，`0` 表示深圳。指数用同一套规则。 |
| `fields1` | 必需 | 控制 `data` 顶层的字段，见 1.3。 |
| `fields2` | 必需 | 控制 `klines` 每行的列，见 1.4。 |
| `klt` | 必需 | K 线周期，见 1.5。 |
| `fqt` | 必需 | 复权方式，见 1.5。 |
| `beg` / `lmt` | 至少给一个 | 取数范围，见 1.6。 |
| `end` | 可选 | 结束日期。 |
| `ut` | 可选 | 常见值 `fa5fd1943c7b386f172d6893dbfba10b`。实测不带也能正常返回。 |

`secid` 的 `market` 取值实测：

```
https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=1.600000&ut=fa5fd1943c7b386f172d6893dbfba10b&fields1=f1,f2,f3,f4,f5,f6&fields2=f51,f53&klt=101&fqt=1&end=20500101&lmt=2
```

`1.600000` → `浦发银行`（market 1）。`0.000001` → `平安银行`（market 0）。`1.000001` → `上证指数`，`0.399001` → `深证成指`，`1.000300` → `沪深300`。市场号写错时返回 `rc: 100`：

```
https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=0.600000&ut=fa5fd1943c7b386f172d6893dbfba10b&fields1=f1,f2,f3&fields2=f51,f53&klt=101&fqt=1&end=20500101&lmt=2
→ {"rc":100,"rt":1,"svr":183120239,"lt":1,"full":1,"dlmkts":"","dsc":"0","data":null}
```

### 1.2 响应结构

```
{"rc":0,"rt":17,"svr":181669690,"lt":1,"full":0,"dlmkts":"","dsc":"0",
 "data":{"code":"600000","market":1,"name":"浦发银行","decimal":2,"dktotal":6404,"preKPrice":9.18,
         "klines":["2026-09-30,9.22,9.48,9.49,9.16,1474848,1386209937.00,3.59,3.27,0.30,0.44", ...]}}
```

`rc` 实测取值：

| rc | 含义 | 触发方式 |
| --- | --- | --- |
| 0 | 成功 | |
| 100 | 参数取值非法 | `secid=5.600000`、`klt=99` |
| 102 | 缺少必需参数 | 缺 `fields1`、缺 `fields2`、缺 `fqt`、`fqt=3`、只给 `end` 而 `beg` 与 `lmt` 都缺 |

`data` 顶层字段由 `fields1` 决定，`klines` 为字符串数组，每行用逗号连接被 `fields2` 选中的列。

### 1.3 fields1

`fields1` 逐项对照，实测用 `fields1=f1` 与 `fields1=f1,f2,f3,f4,f5,f6` 两次请求比较 `data` 的键：

| fields1 | data 里的键 | 含义 |
| --- | --- | --- |
| `f1` | `code` | 证券代码 |
| `f2` | `market` | 市场号 |
| `f3` | `name` | 证券名称 |
| `f4` | `decimal` | 价格小数位数 |
| `f5` | `dktotal` | 该证券历史 K 线总条数（与请求范围无关） |
| `f6` | `preKPrice` | 本次返回的第一根 K 线的前收盘价 |

`fields1=f1` 时 `data` 只剩 `code` 与 `klines`：

```
https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=1.600000&ut=fa5fd1943c7b386f172d6893dbfba10b&fields1=f1&fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61&klt=101&fqt=1&beg=20240101&end=20240105
→ {"rc":0,...,"data":{"code":"600000","klines":["2024-01-02,5.48,5.45,5.50,5.45,220667,146066304.00,0.91,-0.37,-0.02,0.08", ...]}}
```

`preKPrice` 的含义用 1.2 的示例核对：返回的第一根是 2026-09-30，其 `涨跌额` 为 `0.30`、`收盘` 为 `9.48`，`9.48 - 0.30 = 9.18`，与 `preKPrice` 一致。

### 1.4 fields2：klines 的列

`fields2` 逐项对照。取 `secid=1.600000`、`klt=101`、`fqt=1`、`end=20500101&lmt=1` 的最后一行：

```
2026-10-13,9.67,9.65,9.70,9.58,344352,331521401.00,1.24,-0.21,-0.02,0.10
```

| fields2 | 列名 | 本行取值 | 单位与算法 |
| --- | --- | --- | --- |
| `f51` | 日期 | `2026-10-13` | 日线为 `YYYY-MM-DD`；分钟线为 `YYYY-MM-DD HH:MM` |
| `f52` | 开盘 | `9.67` | 元 |
| `f53` | 收盘 | `9.65` | 元 |
| `f54` | 最高 | `9.70` | 元 |
| `f55` | 最低 | `9.58` | 元 |
| `f56` | 成交量 | `344352` | 手 |
| `f57` | 成交额 | `331521401.00` | 元 |
| `f58` | 振幅 | `1.24` | 百分比，`(最高-最低)/前收盘×100` |
| `f59` | 涨跌幅 | `-0.21` | 百分比 |
| `f60` | 涨跌额 | `-0.02` | 元 |
| `f61` | 换手率 | `0.10` | 百分比 |

`f58` 用本行核对：`(9.70-9.58)/9.67×100 = 1.24`，其中 `9.67` 是前一交易日 2026-10-12 的收盘。`f60` 核对：`9.65-9.67 = -0.02`。

`f61` 用 `f56` 与流通股本核对：`344352` 手 = 34,435,200 股，除以流通股本 33,305,838,300 股得 0.1034%，与 `0.10` 一致。

列的顺序与 `fields2` 里写的顺序一致，且只输出被点名的列。实测 `fields2=f51` 只返回日期，`fields2=f51,f53` 只返回日期与收盘：

```
https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=1.600000&ut=fa5fd1943c7b386f172d6893dbfba10b&fields1=f1,f2,f3,f4,f5,f6&fields2=f51,f53&klt=101&fqt=1&beg=20240101&end=20240105
→ ["2024-01-02,5.45","2024-01-03,5.49","2024-01-04,5.47","2024-01-05,5.53"]
```

### 1.5 klt 与 fqt

`klt` 实测：

| klt | 含义 | `beg=0&end=20500101` 时的条数（600000） |
| --- | --- | --- |
| `1` | 1 分钟 | 120 |
| `5` | 5 分钟 | 1512 |
| `15` | 15 分钟 | 504 |
| `30` | 30 分钟 | 252 |
| `60` | 60 分钟 | 126 |
| `101` | 日线 | 6404 |
| `102` | 周线 | 1354 |
| `103` | 月线 | 323 |

`klt=99` 返回 `rc: 100`。周线与月线的 `f51` 是该周期的最后一个交易日：

```
klt=102 → ["2026-09-30,9.48","2026-10-09,9.54","2026-10-13,9.65"]
klt=103 → ["2026-08-31,9.16","2026-09-30,9.48","2026-10-13,9.65"]
```

`fqt` 实测：

| fqt | 含义 |
| --- | --- |
| `0` | 不复权 |
| `1` | 前复权 |
| `2` | 后复权 |

三者确实产生不同数值。以 600000 的 2026-07-13 收盘为例：

```
https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=1.600000&ut=fa5fd1943c7b386f172d6893dbfba10b&fields1=f1&fields2=f51,f53&klt=101&fqt=<0|1|2>&beg=20240101&end=20500101
fqt=0 → 2026-07-13 收盘 9.19
fqt=1 → 2026-07-13 收盘 8.77
fqt=2 → 2026-07-13 收盘 97.15
```

指数上 `fqt` 无效，`fqt=0` 与 `fqt=1` 返回相同的值（用 `secid=1.000001` 核对）。

### 1.6 beg、end、lmt 的配合

`beg` 与 `end` 都是 `YYYYMMDD`。`end=20500101` 表示取到最新。

`lmt` 的行为取决于 `beg` 与 `end` 是否同时给出：

| 组合 | 行为 | 实测 |
| --- | --- | --- |
| `beg` 与 `end` 都给出 | `lmt` 被忽略，返回区间内的全部 K 线 | `beg=0&end=20500101&lmt=3` 返回 6404 行 |
| 只给 `end` | 返回最新的 `lmt` 行 | `end=20500101&lmt=3` 返回 2026-10-09 起的 3 行 |
| 只给 `beg` | 返回最早的 `lmt` 行 | `beg=0&lmt=3` 返回 1999-11-10 起的 3 行 |
| 都不给 | `rc: 102` | |

因此「取最近 N 根」要写成 `end=20500101&lmt=N` 并省略 `beg`。

`klt=1` 无视 `beg`、`end`、`lmt`，总是返回当前交易日的全部分钟线。用 `beg=20261009&end=20261010`、`beg=20261001&end=20261013`、`end=20500101&lmt=1000` 三次请求，返回的都是同一天的 120 行。

### 1.7 分钟线能取多长的历史

用 `beg=0&end=20500101` 与 `beg=20200101&end=20500101` 两种写法请求，得到的窗口相同，说明这是服务端的固定上限，与请求参数无关。按交易日统计（2026-10-13 观测）：

| klt | 条数 | 交易日数 | 最早一根 |
| --- | --- | --- | --- |
| `1` | 120 | 1 | 2026-10-13 09:31 |
| `5` | 1512 | 32 | 2026-08-21 09:35 |
| `15` | 504 | 32 | 2026-08-21 09:45 |
| `30` | 252 | 32 | 2026-08-21 10:00 |
| `60` | 126 | 32 | 2026-08-21 10:30 |

`klt=5/15/30/60` 的窗口一致，都落在 2026-08-21 到 2026-10-13 的 32 个交易日。`klt=1` 只给当天。这一窗口在下列证券上逐一核对，结果相同：

| secid | 名称 | market |
| --- | --- | --- |
| `1.600000` | 浦发银行 | 1 |
| `0.000001` | 平安银行 | 0 |
| `0.000002` | 万科A | 0 |
| `0.300750` | 宁德时代 | 0 |
| `1.688981` | 中芯国际 | 1 |
| `1.000300` | 沪深300 | 1 |

分钟线支持复权。`klt=5` 的 `fqt=0` 与 `fqt=1` 在最近没有除权事件时数值相同，`fqt=2` 明显不同：

```
https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=1.600000&ut=fa5fd1943c7b386f172d6893dbfba10b&fields1=f1&fields2=f51,f53&klt=5&fqt=<0|1|2>&end=20500101&lmt=3
fqt=0 → ["2026-10-13 11:20,9.63","2026-10-13 11:25,9.64","2026-10-13 11:30,9.65"]
fqt=1 → 同上
fqt=2 → ["2026-10-13 11:20,102.82","2026-10-13 11:25,102.89","2026-10-13 11:30,102.95"]
```

K 线接口按证券返回历史，遇到停牌只是把最后一根停在停牌前最后一个交易日。用 `klt=101&fqt=1&end=20500101&lmt=3` 核对：

| --- | --- | --- | --- |
| `1.601198` | 东兴证券（停牌） | 2783 | `2026-09-14` |
| `0.002388` | 新亚制程（停牌） | 3826 | `2026-09-30` |
| `1.600001` | 邯郸钢铁（已退市） | 2753 | `2009-12-15` |
| `1.600701` | 退市工新（已退市） | 5451 | `2021-04-26` |
| `1.600723` | 首商股份（已退市） | 5993 | `2021-09-15` |
| `0.000003` | PT金田A（已退市） | 2423 | `2002-04-26` |

## 二、东方财富全市场列表接口

### 2.1 请求

```
https://push2.eastmoney.com/api/qt/clist/get
```

必需参数至少包括 `fs`：缺 `fs` 返回 `rc: 102`。`ut` 不带也能返回；`fields` 不带时返回默认字段集 `f1` 到 `f29`。分页用 `pn`（页码，从 1 开始）与 `pz`（每页条数），排序用 `fid`（排序字段）与 `po`（`1` 降序、`0` 升序），`np=1` 时 `data.diff` 是数组，`np=2` 时是对象。

### 2.2 pz 的上限

`pz` 的上限是 100。用 `fs=m:0+t:6,m:1+t:2`（沪深主板，`total` 为 3488）逐档测试：

| pz | 实际返回条数 |
| --- | --- |
| 50 | 50 |
| 100 | 100 |
| 101 | 100 |
| 200 | 100 |
| 500 | 100 |
| 1000 | 100 |
| 20000 | 100 |

所以取完沪深主板需要 35 页。第 35 页返回 88 条（`pn=35&pz=100`），合计 3488，与 `total` 一致。

### 2.3 fs 的取值

| fs | 覆盖范围 | `total`（2026-10-13） | 示例代码 |
| --- | --- | --- | --- |
| `m:0+t:6` | 深圳主板 A 股 | 1642 | `000715`、`003037` |
| `m:0+t:80` | 创业板 | 1453 | `301660`、`300107` |
| `m:1+t:2` | 上海主板 A 股 | 1846 | `603188`、`600202` |
| `m:1+t:23` | 科创板 | 621 | `688655`、`688004` |
| `m:0+t:81+s:2048` | 北交所 | 361 | `920821`、`920592` |
| `m:0+t:7` | 深圳 B 股 | 59 | `200530`、`200505` |
| `m:1+t:3` | 上海 B 股 | 55 | `900948`、`900937` |
| `m:0+t:6,m:1+t:2` | 沪深主板 A 股 | 3488 | |
| `m:0+t:6,m:0+t:80,m:1+t:2,m:1+t:23` | 沪深全部 A 股（不含北交所） | 5562 | |
| `m:0+t:6,m:0+t:13,m:0+t:80,m:1+t:2,m:1+t:23,m:0+t:81+s:2048` | 含北交所的全部 A 股 | 5923 | |

取沪深主板的全部代码与名称，用：

```
https://push2.eastmoney.com/api/qt/clist/get?pn=1&pz=100&po=1&np=1&fltt=2&invt=2&fid=f12&fs=m:0+t:6,m:1+t:2&fields=f12,f13,f14
```

`f12` 是代码，`f13` 是市场号（`0` 深圳、`1` 上海），`f14` 是名称。这三个字段可以拼出 K 线接口要的 `secid`。`f14` 会带填充空格，例如 `000002` 的名称是 `万  科Ａ`（「万」与「科」之间有空格，字母是全角），使用时需要自行去掉空白。

### 2.4 常用字段

以 `f12=600000` 那一行为准，与 `https://push2.eastmoney.com/api/qt/stock/get?secid=1.600000` 以及 1.4 的 K 线列交叉核对：

| 字段 | 含义 | 600000 取值 | 交叉核对来源 |
| --- | --- | --- | --- |
| `f2` | 最新价 | `9.65` | K 线 `f53` |
| `f3` | 涨跌幅（%） | `-0.21` | K 线 `f59` |
| `f4` | 涨跌额 | `-0.02` | K 线 `f60` |
| `f5` | 成交量（手） | `344352` | K 线 `f56` |
| `f6` | 成交额（元） | `331521401` | K 线 `f57` |
| `f7` | 振幅（%） | `1.24` | K 线 `f58` |
| `f8` | 换手率（%） | `0.1` | K 线 `f61` |
| `f9` | 市盈率（动） | `5.19` | 腾讯快照第 52 项 |
| `f10` | 量比 | `0.68` | 腾讯快照第 49 项 |
| `f12` | 代码 | `600000` | |
| `f13` | 市场号 | `1` | |
| `f14` | 名称 | `浦发银行` | |
| `f15` | 最高 | `9.7` | K 线 `f54` |
| `f16` | 最低 | `9.58` | K 线 `f55` |
| `f17` | 今开 | `9.67` | K 线 `f52` |
| `f18` | 昨收 | `9.67` | 前一日 K 线 `f53` |
| `f20` | 总市值（元） | `321401339595` | 腾讯快照第 73 项 × 最新价 |
| `f21` | 流通市值（元） | `321401339595` | 腾讯快照第 72 项 × 最新价 |
| `f23` | 市净率 | `0.43` | 腾讯快照第 46 项 |
| `f24` | 60 日涨跌幅（%） | `10.03` | 前复权 K 线第 61 根 |
| `f25` | 年初至今涨跌幅（%） | `-19.72` | 前复权 K 线 2025 年最后一根 |
| `f115` | 市盈率（TTM） | `6.27` | 腾讯快照第 39 项 |

`f24` 与 `f25` 是按前复权价算的。用 600000 的前复权日线核对：第 61 根（2026-07-13，收盘 8.77）到最新收盘 9.65 得 `+10.03%`，与 `f24` 一致；2025 年最后一根（2025-12-31，收盘 12.02）到 9.65 得 `-19.72%`，与 `f25` 一致。用不复权价算得 `+5.01%` 与 `-22.43%`，与接口值不符。

### 2.5 停牌、退市、新股

沪深主板 3488 行里有 301 行的 `f2` 为字符串 `"-"`。按名称粗分：113 个名称含「退」，117 个含「ST」，其余 71 个。停牌与未上市的区分在于 `f18`：

| secid | 名称 | 情形 | `f2` | `f5` | `f18` | `f20` | `f23` |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `1.601198` | 东兴证券 | 停牌 | `-` | `-` | `13.06` | `42215738491` | `1.39` |
| `0.002388` | 新亚制程 | 停牌 | `-` | `-` | `9.1` | `4609461402` | `4.89` |
| `0.001381` | 皇冠新材 | 尚未上市 | `-` | `-` | `-` | `-` | `-` |

停牌时昨收与市值、市净率仍然有值；尚未上市时 `f18`、`f20`、`f21`、`f23`、`f24`、`f25`、`f115` 全是 `-`。

名称里带「退」的已退市证券仍然出现在列表里，例如 `002018` 华信退、`600701` 退市工新。这个列表包含已退市证券，取「当前可交易股票」需要按 `f2` 是否为 `-` 或者按名称自行过滤。

## 三、腾讯快照

### 3.1 请求

```
https://qt.gtimg.cn/q=sh600000,sz000001
```

`https://web.sqt.gtimg.cn/q=sh600000,sz000001` 返回完全相同的字段。代码前缀为 `sh`、`sz`、`bj`。返回头是 `Content-Type: text/html; charset=GBK`，响应体按 GBK 解码。

响应体每个证券一行，形如 `v_sh600000="...";`，字段之间用 `~` 连接。查不到的代码返回：

```
https://qt.gtimg.cn/q=sh999999,sz888888
→ v_pv_none_match="1";
```

### 3.2 单次请求能带多少只代码

代码数量有硬上限 900 只。超过 900 只时服务端返回 HTTP 200，响应体是纯文本 `too many codes`：

```
curl --http1.1 -s "https://qt.gtimg.cn/q=<900 只代码，逗号分隔>" | head -c 20
→ v_sz002061="51~浙江交
curl --http1.1 -s "https://qt.gtimg.cn/q=<901 只代码，逗号分隔>"
→ too many codes
```

逐档实测（HTTP/1.1）：

| 代码数量 | URI 长度 | HTTP 状态 | 响应体 |
| --- | --- | --- | --- |
| 890 | 8057 | 200 | 890 条记录 |
| 900 | 8102 | 200 | 900 条记录 |
| 901 | 8111 | 200 | `too many codes` |
| 908 | 8174 | 200 | `too many codes` |
| 909 | 8183 | 414 | HTML 错误页 |

请求 URI 的长度还有一层限制。用 HTTP/2（curl 8.7.1 在 HTTPS 上的默认协议）时，624 只可以通过，625 只时服务端发出 `GOAWAY error=11`，curl 报 HTTP 000：

| 协议 | 实测边界 |
| --- | --- |
| HTTP/1.1 | 900 只可用；901 只起返回 `too many codes`；URI 长到 8183 字节时返回 `414 URI Too Long` |
| HTTP/2 | 624 只可用；625 只时 `GOAWAY error=11` |

在 600 只代码后面追加 800 个无意义字符会让请求失败，说明 URI 长度本身也参与判定：

```
curl -s "https://qt.gtimg.cn/q=<600 只代码>&p=<800 个字符>" -o /dev/null -w '%{http_code}'
→ 000
```

实际使用建议按 500 到 600 只一批。
